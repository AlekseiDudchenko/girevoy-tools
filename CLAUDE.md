# Инструменты гиревика

Калькуляторы и графики для гиревиков, тренеров и организаторов на `tools.vsegiri.com`.
Замысел, решения и граница с архивом — `docs/vision-tools.md` в репозитории
[`girevoy-archive`](https://github.com/AlekseiDudchenko/girevoy-archive/blob/develop/docs/vision-tools.md).
Активные задачи, приоритеты и статус — в GitHub Issues этого репозитория.

## Граница с архивом — не нарушать

- Архив (`vsegiri.com`) — факты из протоколов. Здесь — ввод пользователя и арифметика.
  Если число нельзя показать в PDF протокола, это не архив, и наоборот: здесь
  не публикуются результаты соревнований как факты.
- Данные текут только из архива сюда: инструменты могут читать публичную выгрузку
  архива и никогда ничего в архив не пишут.
- Вычисленное (коэффициент, зачётный результат, разрядный балл, прогноз) не называется
  «результатом» и не показывается без исходного числа подъёмов.
- Рекордов и номинаций нет, как и в архиве.
- Ни сервера, ни аккаунтов: всё считается в браузере, введённое на сервер не уходит.
  Состояние — в адресе страницы (ссылку можно отправить), удобства — в `localStorage`.

## Структура

```
CLAUDE.md               этот файл
README.md               быстрый старт
src/brand.js            название, адреса сайта и архива, шаблон <title>
src/tools.js            перечень инструментов: главная, навигация, статус ready/planned
src/layout.js           оболочка страницы: head, шапка, подвал
src/html.js             esc() — всё, что вставляется в шаблоны
src/pages/index.js      все страницы сайта
src/pages/<имя>.js      страница: path, title, description, body(), scripts
src/lib/                чистые функции расчёта и разметки: общие для сборки, браузера и тестов;
                        сборка копирует их в dist/lib/, браузер импортирует из /lib/
src/lib/coefficients.js       коэффициенты: подъёмы на тяжёлой, состояние в адресе
src/lib/coefficients-view.js  коэффициенты: графики SVG, легенды, таблица — строки HTML
assets/style.css        токены тем и стили; значения цветов совпадают с архивом
assets/fonts.css, fonts/  копия шрифтов архива — руками не править
assets/<инструмент>.js  поведение страницы в браузере (ES-модуль), импорт расчёта — './lib/…'
scripts/build.mjs       сборка в dist/: страницы, assets/, src/lib/ → lib/, sitemap.xml, robots.txt
tests/*.test.mjs        node:test — расчёты и собранные страницы
.github/workflows/deploy.yml  проверка на PR, деплой main на Cloudflare Pages (пока не настроен)
```

## Команды

```sh
npm run build    # собрать сайт в dist/
npm test         # тесты
npm run check    # сборка и тесты — то же, что в CI
npm run preview  # сборка и сервер на :8081
```

Зависимостей нет: Node 22, `node:test`. Не добавлять фреймворки и сборщики без причины.

## Интерфейс

- Цвета только через токены в `assets/style.css`, светлая и тёмная тема. Значения
  токенов совпадают с `public/style.css` архива: инструменты и архив выглядят одним сайтом.
  Цвет гири — `--bell-16/24/32`, как в оглавлении турнира архива.
- Стили и браузерный JavaScript — в `assets/`, не в шаблонах. В HTML встраиваются только
  данные конкретной страницы (`<script type="application/json">`).
- Расчёт — чистые функции в `src/lib/`, их импортирует и страница, и тест. Логику
  в обработчиках событий не дублировать. Модули `src/lib/` импортируют только друг
  друга (относительно, `./…`) — они же работают в браузере из `/lib/`.
- Разметку, которую меняет браузер (график, таблица), рисует одна функция из `src/lib/`:
  сборка — для значений по умолчанию, браузер — после каждого изменения.
- Цвет в SVG — классом из `assets/style.css`, без атрибутов `fill`/`stroke` с цветом.
  Переменный цвет (например, гири) — свойством вида `--c-light: var(--bell-24)` на
  корневом блоке.
- Числа классом `.n`. Широкие таблицы — в `.table-wrap`. Ширина телефона — без
  горизонтальной прокрутки страницы.
- Без JavaScript страница показывает осмысленное состояние по умолчанию (например,
  таблицу для значений по умолчанию), а не пустоту.
- Перед коммитом страницы — посмотреть скриншот в светлой и тёмной теме и на ширине
  телефона, а не только собранный HTML.

## Git

- Никогда не коммитить и не пушить напрямую в `main`.
- Пока ветки `develop` в процессе нет: каждая задача — новая ветка от актуального
  `origin/main` (`git fetch origin main && git switch -c <ветка> origin/main`), PR в `main`,
  ревью, слияние. Промежуточный шаг с PR в `develop` добавим позже.
- `main` — продакшен, после настройки деплоя публикуется автоматически.
- PR ссылается на Issue. Когда работа по Issue слита в `main`, проверить, что Issue
  закрыт, и закрыть вручную, если нет.
- Коммитить и пушить небольшими шагами; в конце сессии рабочее дерево чистое.
